Connect your intelligence backend

The frontend is deployed. The API, customer database, trained models and agent checkpoints need a persistent backend service before the application can be used.

1. Deploy the prepared backend

The source project includes render.yaml and backend/Dockerfile. Push the repository to your own Git host and create a Render Blueprint from it, or run the Docker backend on a host with a persistent volume.

The prepared Render blueprint uses a paid service with a persistent disk. Review the plan in your hosting account before creating it. No backend hosting service has been provisioned by this frontend deployment.

2. Configure its environment

  • Set JWT_SECRET to a unique random value of at least 48 characters. Keep it in the backend host's secret settings.
  • Set CORS_ORIGINS to this frontend's exact HTTPS origin, without a trailing slash.
  • Keep ENVIRONMENT=production. The blueprint stores the SQLite database, model artifacts and LangGraph checkpoints on one persistent disk; use only one backend instance.
  • Leave LLM settings empty to use the local tool router. Optional provider credentials belong only on the backend.

3. Provision your administrator

In the backend host's service shell, run python -m app.admin and enter your own account details. Production registration is disabled. Confirm that /api/health responds successfully.

4. Connect Vercel

In the Vercel project environment settings, add VITE_API_BASE_URL=https://YOUR-BACKEND-HOST/api for Production, then redeploy. The connection screen will be replaced by sign-in.

After signing in, open Data Import to generate a synthetic demo dataset, then Model Performance to train and score it. This deployment does not copy any local accounts or datasets.
